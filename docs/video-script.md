## 二、拍摄前准备(一次性)

### 2.1 生成演示规则文件

存为仓库根目录 `demo-rules.json`(**拍完删除或别提交**,阈值不是默认值)。字段名来自 `packages/shared` 的 `RulesFileSchema`,partial 文件自动与默认值合并:

```json
{
  "volumeThreshold": { "bytesPer10min": 20971520, "bytesPerHour": 52428800 }
}
```

即 20MB/10min、50MB/h。mock 的 `backup-agent`(8% 拍概率、单拍 0.2~5MB)几分钟内必触发。

### 2.2 三个终端启动(注意参数,直接照抄)

```bash
npm install && npm run web:build

# 终端 1:采集端。--db 必须给(mock 默认内存库,不给历史视图全空);--rules 指向演示规则
npm run collector:mock -- --db=/tmp/netwatch-demo.db --rules=$(pwd)/demo-rules.json

# 终端 2:展示端。NETWATCH_DB 指向同一个库文件
NETWATCH_DB=/tmp/netwatch-demo.db npm run web
```

### 2.3 浏览器与素材预热

- 预开三个标签直达视图(URL 只有 `view` 参数,**history 的时间范围不进 URL,需现场点击**):
  - `http://127.0.0.1:8787/?view=live`
  - `http://127.0.0.1:8787/?view=history`
  - `http://127.0.0.1:8787/?view=alerts`
- **开录前先让采集端跑 10 分钟**:历史面积图有形状、NEW 徽标和告警大概率已经攒出几条,挑得到的镜头更从容。
- webhook 接收端(给 S6 分屏用):本地起一个最简接收器即可,例如 `nc -l 9999`,规则里配 `"notify": { "webhookUrl": "http://127.0.0.1:9999/hook" }`(加进 demo-rules.json)。不要用公开请求 bin。
- 录屏设置:2560×1440 或系统级放大 UI,60fps(保住数字滚动观感);开勿扰,清桌面通知;深色主题全屏。
- 真实流量镜头(仅 S4 需要):`sudo npm run collector` 跑真实源,正常浏览/同步几分钟,让真实域名解析出来。**录完检查画面里自己的域名/IP,后期打码。**
